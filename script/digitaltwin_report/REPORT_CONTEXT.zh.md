# 工艺与数据上下文（中文）

## 工艺背景
- 污水厂数字孪生项目，进水后分两期四线进入生化池。
- 每条线前 4 池厌氧/缺氧，后 6 池好氧。
- 关注点：反硝化段 NOx、出水端 EFF 指标、碳源投加策略。

## 数据来源口径
- 当前运行态主来源：`sim_recorder`
- 预测态主来源：`sim_predict`
- 报告重点字段：`CSTR*_SNOx` 和 `EFF*`
- 峰值判定：`daily_max >= 1.8 * daily_mean`
- 命名规则解释：`CSTRA_B_*` 中，`A` 是线号（1~4），`B` 是池号。

## 加碳策略三表
1. `carbon_opt_task`
- 单次任务摘要（status/remark/边界/目标等）
2. `carbon_opt_schedule`
- 10分钟粒度执行计划曲线
3. `carbon_opt_front`
- 当前最终生效曲线（前端/下发优先视图）

## 三表联合诊断逻辑
- `task_count` 仅作任务运行参考，不应直接用于判断“加碳调节是否频繁”（因任务可能按小时固定触发）。
- `latest_task` 非 SUCCESS：优先检查优化脚本日志与配置有效性。
- `front_current` 缺失：可能导致前端/下发链路退化。
- `schedule_next_60m` 缺失：说明计划展开或写入链路存在问题。

## 三表勾稽关系（必须按此理解）
1. `carbon_opt_task`
- 记录单次优化/手动任务的元信息（目标、边界、状态、备注）。
- `task_id` 是后续链路主键。

2. `carbon_opt_schedule`
- 把任务策略数组按 10 分钟粒度展开，形成执行计划。
- 每个计划点通过 `task_id` 关联到任务。

3. `carbon_opt_front`
- 将“最终生效曲线”按 `exec_time` upsert（历史+未来）。
- 前端和控制下发优先读取这里，反映当前实际应执行值。

4. 下发链路
- `set_carbon_opc` 读取生效曲线并执行控制写入（OPC）。

5. 报告解释要求
- 必须把 `snox_target`、`front_snox`、`snox_gap` 联合解释。
- gap > 0 代表当前 NOX 高于目标；gap < 0 代表低于目标。

## 报告语气
- 工程化、可执行、避免空泛描述
- 明确指出风险与优先级

## 缺失值解释规则（N/A / NaN）
- 实验室 `water_quality_pool` 的 `parm_mlss/parm_mlvss` 并非每个批次都有，缺失时应优先按同线向前回溯最近有效值。
- 若 line1~4 全部为空，优先怀疑：字段映射错误、同步链路缺字段、该批次化验尚未回填。
- 若仅部分 line 为空，倾向于分线化验延迟或局部采样缺失，不应直接判定工艺异常。
- 报告中遇到缺失值时，应先解释“数据可得性问题”再给工艺判断，避免把数据缺失误判为工艺失控。

## 加碳稳态高投加识别
- 若“调整频率低（低 adjust_ratio）但加碳值长期偏高（高均值/高设定）”，应视为潜在优化问题，而非“策略健康”。
- 典型解释：目标过紧、预测偏高、反馈不足导致高位设定长期维持。
- 报告需要明确给出降碳试探建议与验证闭环（2-3个周期跟踪 NOX/EFF），而不是仅描述“稳定”。
